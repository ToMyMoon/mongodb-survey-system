# 第二阶段结构与兼容设计

第二阶段在第一阶段 app.py、engine.py、db.py 和原生前端上扩展，没有替换问卷系统。核心填写引擎、发布快照、正式答卷、匿名和重复限制保留，新增逻辑在 template_library.py 和 static/library.js。

## 数据组织

- question_templates：完整固定题目、ownerId、sourceTemplateId、来源问卷/版本/实例、创建时间、兼容旧删除字段、内容及统计摘要、幂等 requestId 和请求摘要。
- template_entries：userId、templateId、removed、移除时间及分类选择标记，组合唯一；正文和作者归属不因个人移除而改变。
- question_shares：templateId、userId、grantedBy、active 和时间，模板与接收者组合唯一。
- question_banks：ownerId、名称、说明、删除状态、isDefault；部分唯一索引保证每人一个默认题库。
- question_bank_items：bankId、templateId、内容摘要、active、排序及时间。同库模板组合唯一，活动内容摘要有部分唯一索引。
- template_sources：模板与来源问卷/发布版本/题目实例的显式映射，兼容旧发布内容。
- template_state：一条 catalogue 协调记录，在目录写事务开始时增加计数，协调共享撤销、选用、删除、恢复和分类去重。

选择题选项仍嵌入题目；题库、共享及来源关联使用独立集合，避免复制正文或单文档关联数组无限增长。模板是单题，不另建模板编辑或版本发布系统；每次修改后另存形成新模板，以父来源关系表达历史及分支。

## 与问卷关联

surveys.questions 保留完整副本及原实例 _id。服务器选用模板时生成新实例与选项 ID，sourceTemplateId 记录直接使用来源；从草稿另存新模板时保留原来源，并在 savedTemplateIds 中记录从此实例保存过的模板。新发布快照保留这些字段，普通问卷更新不得更改它们。

同一实例连续另存时，使用 savedTemplateIds 中最近保存的模板作为新模板的直接父来源；尚未另存过才使用初始 sourceTemplateId。原始使用关系仍保留，来源链和统计绑定各司其职。重复内容查重也包含父来源，避免改回旧内容时丢失新的派生关系。普通问卷保存严格校验来源列表及其不可改性，模板保存和选用只接受整数 revision。

从旧发布内容保存模板为旧快照新增 template_sources，不回写快照；若是当前发布版本，同时为当前问卷编辑对象补充后续使用的来源记录，使关闭后改题另存仍保留父来源。草稿来源映射只对当前实例及后续保留绑定的新快照生效，不根据同一实例 ID 倒推未明确关联的旧快照。

responses、answers 及 payloadHash 解释不变。新答案通过发布快照找来源，旧答案通过显式映射接入；一次统计中按发布版本和题目实例建立唯一匹配表，避免直接关系与映射交叠导致重复累计。同卷多个实例分别统计。

## 内容与统计

文本保留并逐字比较，数值精确解析并统一表示；选项比较文字和顺序，不比较技术 ID。题库内容摘要包含 required，统计摘要排除 required；顺序位置和跳转不参与题目正文摘要。未完成草稿的非法数值标记为未完成差异，不能进入有效模板统计，也不使使用情况页面失败。

统计只从当前用户自己的问卷枚举快照，校验题目来源及内容后读取对应答卷；不将来源链所有祖先/后代自动合并。选择题按实例选项位置对应模板选项。人数使用内部账号去重，输出不泄露匿名账号；单选人数逐选项去重、多选及数值按回答累计。数值聚合使用十进制计算，平均值以十进制字符串输出。

求和精度根据所有数值的最高位、最低位和回答数量动态设置，以精确保留大数相抵后的细小值；得到精确总和后，再以 50 位精度计算平均值，不采用固定 50 位精度先累加。

模板列表及选题弹窗使用请求序号，只应用最新一次筛选的结果；失败明确提示并提供重试。模板保存响应未知时锁定分类，保留原请求标识和内容供重试，明确失败后才允许重新选择。历史恢复成功关闭旧弹窗并刷新列表。

## 权限及并发

来源正文逐节点检查所有者或有效共享，无法访问的节点只提供占位关系。所有统计与引用查询只遍历自己问卷；共享模板接口不返回他人的来源问卷标识。个人移除只更新当前用户的 template_entries 并停用自己的分类，正文、其他用户收录与共享授权不变；恢复检查当前权限，只恢复自己的无冲突原分类。无权限来源节点附说明，不返回题干、作者或来源问卷。

目录修改在真实 MongoDB 事务中协调，同时写问卷时与其 revision 编辑锁衔接。重复保存通过 ownerId/requestId 唯一索引和请求摘要重放；模板与映射及本次分类一起提交。目录协调记录采用全局串行写，适合本机课程规模，降低并发规则复杂度；不代表高吞吐设计，后续若扩容可拆分更细粒度协调。

## 环境和数据

第二阶段独立 venv、.mongo、27019 端口、副本集 survey-stage2-rs 和数据库 survey_coursework_stage2，网页 5001。首次导入只读第一阶段，通过源端快照事务读取四个业务集合，目标端事务写入并逐集合校验摘要；目标非空拒绝覆盖，不迁移会话。

业务和来源测试使用随机测试库。第一阶段文件摘要校验记录保存在上级文档目录；不向第一阶段写源码、测试、报告或新业务数据。


## 2026-10-27 个人剪贴板体验调整

启动时在目录协调事务中一次性回填个人收录：旧模板 deleted 转为作者个人 removed，再清除全局删除标记；旧失效共享保持失效。question_templates.deleted 仅兼容旧格式，不再承载个人删除语义。迁移标记 personalEntriesVersion 保证重复启动不覆盖个人选择，不回写问卷、发布快照和答卷。

题库首次加载确保默认题库存在，旧同名可用库沿用；旧未分类记录尝试一次性归入，用户后续明确取消的分类不自动加回。保存弹窗列出默认题库及全部已有题库，末尾使用与复选项对齐的“＋ 新建题库”。点击后打开单独名称弹窗，提供创建和取消。创建调用 POST /api/banks，成功后加入本次可选列表并勾选，取消默认库勾选，保留其他选择；模板保存仅提交 bankIds。题库创建独立持久化，之后取消模板保存也保留。取消、空名称或创建失败不改动选择，失败保留输入供重试。后端 newBanks 原子保存协议作为兼容入口保留，当前界面不再使用。默认库已有相同内容则跳过该关联并提示，其他自定义题库冲突仍整体回滚。“全部题库”查询模板集合，不按分类关联展开，避免同一 ID 重复。

账号采用原 Cookie 登录机制，窗口间仍共享会话。新前端发送 X-Survey-User，服务器写入前对照实际 Cookie 账号，不一致返回 409 account_changed。响应携带实际身份；前端忽略旧账号响应，以不含凭证的 storage 通知和窗口 focus/visibilitychange 核对状态，清除旧身份编辑界面，不自动重试写操作。未保存编辑不会自动提交，切换时明确提示；填写草稿仍按原用户键保存在本机。
