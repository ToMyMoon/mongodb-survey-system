# 第一阶段对象设计与业务规则

本文记录截至 2026-10-20 的已确认需求及第一阶段实现。源代码、页面、数据库初始化、启动脚本和测试已完成；测试结果见测试报告.md。

## 存储结构

- `users`：用户。
- `surveys`：问卷身份、当前编辑内容、运行设置和状态。
- `survey_versions`：每次发布时保留的不可变内容快照。
- `responses`：正式提交的答卷和答案。
- 未提交答案只保存在浏览器本地，不建立服务器草稿答卷。
- 统计结果按已提交答卷计算，不单独缓存。

## 对象字段

### 用户 User

| 字段 | 说明 |
| --- | --- |
| `_id` | ObjectId |
| `username` | 必填且唯一，最多 15 个 Unicode 码点 |
| `passwordHash` | 密码哈希，不保存明文 |
| `createdAt` | 后端生成的注册时间 |

用户名允许中文、字母、数字、下划线，不允许空白，区分大小写。注册和登录保持相同处理规则。密码为 8～20 个字符，区分大小写，不允许空白，不增加强制字符组合规则。

用户不保存问卷 ID 数组，通过 `Survey.creatorId` 查询自己的问卷。

### 问卷 Survey

| 字段 | 说明 |
| --- | --- |
| `_id` | ObjectId，问卷稳定身份，供分享链接使用 |
| `creatorId` | 创建者用户 ID |
| `title` | 问卷标题，最多 30 个字符，发布时不能为空 |
| `description` | 可选说明，最多 100 个字符 |
| `status` | `draft` 或 `published` |
| `allowAnonymous` | 是否允许匿名，默认 false |
| `allowMultipleSubmissions` | 是否允许重复填写，默认 false；首次发布后锁定 |
| `deadline` | 截止时间，可不设置 |
| `questions` | 当前编辑内容中的 Question 数组 |
| `publishedVersionId` | 最近一次发布的版本 ID；首次发布前为空 |
| `createdAt` | 创建时间 |
| `updatedAt` | 最近修改时间 |

初始状态为 draft。关闭操作将 published 转为 draft，立即停止接收新的填写提交。进入草稿后可以修改题目、选项、校验与跳转规则，再次发布保留新版本。不保留单独的 closed 状态。

发布期间可以直接调整截止时间。到期与状态分别判断：published 但到期也不能提交；延长截止时间后，只要仍为 published 即可恢复填写。draft 不因延长截止时间自动发布。

首次发布后锁定 allowMultipleSubmissions，包括关闭后重新进入草稿的情形。禁止重复填写按稳定问卷 ID 判断，不因新版本发布而重置。

### 问卷发布版本 SurveyVersion

新增此对象的原因是：关闭后可以修改题目和规则，旧答卷必须仍能通过旧内容解释。

已实现的版本字段如下：

| 字段 | 说明 |
| --- | --- |
| `_id` | 版本唯一标识 |
| `surveyId` | 所属问卷稳定 ID |
| `versionNumber` | 发布版本序号 |
| `title` | 发布时的标题快照 |
| `description` | 发布时的说明快照 |
| `allowAnonymous` | 发布时的匿名许可快照 |
| `questions` | 完整题目、选项、校验和跳转快照 |
| `publishedAt` | 发布时间 |

发布版本不可覆盖修改。关闭后编辑 Survey 的当前内容，旧 SurveyVersion 保留。新提交引用当前发布版本；旧答卷始终引用原版本。截止时间和当前是否开放以 Survey 的实时设置为准。

### 题目 Question

嵌入 Survey.questions 及发布版本的 questions。

| 字段 | 说明 |
| --- | --- |
| `_id` | 稳定题目标识 |
| `type` | 单选、多选、文本、数字 |
| `title` | 题目文字，不设业务长度上限 |
| `required` | 是否必答；页面新添加题目默认 true，可取消 |
| `options` | 选择题的 Option 数组 |
| `validation` | ValidationRule |
| `jumpRules` | JumpRule 数组 |

数组顺序表示题目顺序，不另存序号。问卷题目数不设业务上限。题目 ID 在调整顺序时保持稳定。发布版本区分同一题目在不同发布时的具体内容。

### 选项 Option

字段为 `_id`、`text`，嵌入题目。选项文字不设业务长度上限。同一选择题为 2～10 个选项，不允许重复文字。显示顺序由数组决定，A/B/C 不单独保存；答案和规则引用选项 ID。

### 校验规则 ValidationRule

嵌入题目的 validation，required 不在此处重复保存。

| 题型 | 字段 |
| --- | --- |
| 单选 | 无额外配置，仍须验证是一个合法选项 |
| 多选 | minSelections、maxSelections |
| 文本 | minLength、maxLength；页面新建时 minLength=1，可修改 |
| 数字 | minValue、maxValue、integerOnly；页面新建时 integerOnly=true，可取消 |

未配置的限制表示不限制。边界包含端点。恰好选 N 项用最少和最多均为 N 表达。规则不得自相矛盾：最小值不大于最大值，数量和长度是非负整数，选择数量不超过选项总数，必答多选必须存在非空合法选择，整数区间内必须存在可用整数。配置必须符合题型。

文本保留原文，按 Unicode 码点计数，空格和换行计入；纯空白仍视为未作答。数字允许负数、小数，不允许科学计数法，受题目规则约束；需保留前导零的内容使用文本题。数字 0 是有效答案。

### 跳转规则 JumpRule

字段为 condition、targetQuestionId；targetQuestionId 为 null 表示结束。规则嵌入题目的 jumpRules 数组。

简单条件包含 operator、value（hasAnswer 无需 value）：

- hasAnswer：选择题或数字题是否作答，数字 0 算作答。
- 单选 eq。
- 多选 contains、containsAny、containsAll；containsAll 允许额外选择。
- 数字 eq、gt、gte、lt、lte、between。
- between 的 value 为 `{ min: 下限, max: 上限 }`，包含两端边界。

组合条件包含 operator、conditions：all 为全部满足，any 为至少一个满足，not 对一个直接子条件取反。子条件可以是组合，因此 `not(all(A, B, C))` 合法。不增加 ne，用 not(eq) 表达不等于。

创建规则时默认勾选“有作答”，保存为 all(hasAnswer, 用户条件)，创建者可取消。未作答的普通答案比较返回 false，not 正常取反；取消 hasAnswer 后，空答案可以触发取反条件。必答校验始终先执行。

按规则数组顺序匹配，第一条满足的生效；未命中则下一题，最后一题结束。只允许向后跳或结束；文本题不支持跳转。引用的目标和选项必须合法，操作符与值必须符合题型。

草稿删除或调整内容导致跳转失效时，提示受影响规则，要求修正后才能发布，不自动猜测修改。

已确认并实现：禁止空 all/any，条件树最多五层，根节点计第一层，默认 hasAnswer 包装也计入层数。

### 答卷 Response

| 字段 | 说明 |
| --- | --- |
| `_id` | ObjectId |
| `surveyId` | 稳定问卷 ID |
| `surveyVersionId` | 本次填写对应的发布版本 ID，新增 |
| `respondentId` | 当前登录用户 ID，由后端取得 |
| `submissionCode` | 18 位正整数，MongoDB Long |
| `repeatRestricted` | 后端生成，等于 !survey.allowMultipleSubmissions |
| `isAnonymous` | 本次是否匿名，问卷允许时才能为 true |
| `answers` | Answer 数组 |
| `submittedAt` | 成功提交时间，由后端生成 |

只有成功提交的答卷入库，不设服务器草稿状态。每次提交独立保存，提交后不允许修改。只保存实际有效路径上的答案；后端按对应发布版本重新校验路径、题型、答案和权限。

### 答案 Answer

嵌入 Response.answers，字段为 questionId、value，不单设 _id。

- 单选 value：一个选项 ID。
- 多选 value：不重复的选项 ID 数组。
- 文本 value：字符串。
- 数字 value：数值。

每题最多一个答案对象。未答的非必答题不生成对象。通过 surveyVersionId 查找当时的题目定义，不重复保存题目与选项文字。

## 权限和提交规则

所有填写者须登录。创建者只管理自己的问卷并查看其答卷和统计；其他登录用户通过链接填写。后端检查权限。

匿名表示对创建者隐藏身份，系统内部保留 respondentId，匿名答卷接口不向创建者暴露它。该字段仍用于重复限制和人数去重。

发布要求标题非空、至少一道题、所有题目和规则完整合法；草稿允许暂不完整。必答只校验实际路径，非必答题作答后仍须满足规则。前端及时提示，后端再次校验。

点击提交先弹确认窗口，取消后仍可修改；确认后锁定编辑并正式发送。重复请求复用同一码及同一份提交内容。提交时重新检查状态、截止时间和重复限制。

## 页面输入与操作确认

2026-10-20 增加独立前端校验模块 static/validation.js。账号、标题、说明、选项、数量/长度/数字范围、条件树及跳转目标均在输入或结构调整时检查。填写答案同样在输入阶段检查，未修正不能进入下一题；后端继续独立校验。

超长、非法字符、重复选项、上下限冲突、无合法整数等确定违规立即弹窗并标红。空必填或最少长度、数量尚未满足时先标红并显示正确规则，离开该区域或继续操作时弹窗。中文输入法组合输入结束后再弹窗。修正后恢复正常；未完成的内容仍可保存草稿，硬性格式错误须先修正。

点击“发布”先检查完整性，再弹确认框；取消保持草稿且不发送保存/发布请求，确认后再次检查、保存并发布。发布后底部提供“复制问卷链接”“返回主页”“关闭并进入草稿”。自动复制受限时展示真实链接供手动复制。

发布中修改截止时间后自动保存，连续修改按顺序携带最新 revision；显示保存中、已保存或红色未保存状态。关闭或返回主页前等待保存完成。登录和注册密码框有可切换显示的小眼睛，“退出登录”有确认窗口。

上述默认设置仅用于新建题目，既有问卷和历史发布版本不回填或覆盖；接口缺省限制仍按既有规则解释。

## 本地草稿

同一用户对同一问卷保留一份活动草稿，并缓存前一次保存的版本，供回退。保存各题 ID 对应的答案、submissionCode，以及填写所基于的发布版本 ID。跳转隐藏的答案仍保留在本地，正式提交只纳入有效路径。

恢复和修改草稿不换码；提交成功清除活动草稿，重新填写生成新码。

已确认并实现：每次答案变化自动保存，保留当前及前一次保存快照；回退先确认。旧草稿遇到新发布版本时保留供查看，用户主动开始新版，不自动迁移答案。草稿另存本地题目快照以显示历史选项文字。

## submissionCode

开始新填写时，在浏览器用用户 ID、问卷 ID、当前毫秒时间、128 位随机数组成数组，再进行 SHA-256：

`H = SHA-256([用户ID, 问卷ID, 开始时间, 随机数])`

`submissionCode = 10^17 + (将H解释为整数 mod (9 × 10^17))`

MongoDB 存 Long；浏览器和接口使用 18 位数字字符串，避免精度丢失。刷新、恢复、修改、重试沿用原码；新填写生成新码。哈希映射不能保证无碰撞，由唯一索引兜底。

相同码且用户、问卷、版本、内容一致时返回原结果；不同内容或身份返回冲突，不覆盖。明确确认碰撞才换码，网络超时不能直接换码。身份以登录状态为准，校验码不代替身份认证。

## 禁止重复填写与索引

- users.username 唯一。
- surveys.creatorId 普通索引。
- survey_versions 的 surveyId、versionNumber 组合唯一。
- responses.submissionCode 唯一。
- responses 的 surveyId、respondentId 组合部分唯一，只作用于 repeatRestricted=true 的答卷。
- 另需支持按问卷和发布版本读取答卷的查询索引，具体组合在实现时确定。

部分唯一索引（已由 db.py 创建，并经真实数据库并发测试）：

```javascript
db.responses.createIndex(
  { surveyId: 1, respondentId: 1 },
  {
    name: "unique_single_response",
    unique: true,
    partialFilterExpression: { repeatRestricted: true }
  }
)
```

repeatRestricted 与 respondentId 不能由客户端自行决定。并发时依靠唯一约束保证最多插入一份，不能只依靠先查再存。校验码冲突与重复填写冲突分别处理；相同请求重试仍返回原成功结果。

## 统计

只统计正式答卷，不缓存统计结果。支持整卷和单题统计。

- 提交份数：答卷数。
- 单题回答人数：回答者去重数。
- 单选各选项人数：选择该选项的用户去重数。
- 多选各选项次数：按答卷累计。
- 填空：展示所有有效内容。
- 数字平均值：按有效数值计算，重复提交分别计入。
- 未答和跳过不计入该题回答；零次选项仍展示；无数字答案显示暂无数据。
- 同一人不同次单选选择不同选项，可计入多个选项的人数，界面说明口径。

已确认并实现：默认统计最近发布版本，可以切换历史版本；第一阶段不跨版本合并。

## 实现方案

已确定：简单 HTML 前端、本机 MongoDB、Cookie 配合服务器会话，会话数据保存 MongoDB；设计与 AI 日志先保存在当前文件夹的 Markdown 文档中。用户无后端语言偏好。

后端使用 Python 3.12、Flask、PyMongo，网页服务使用 Waitress。会话固定有效八小时，Cookie 保存随机会话标识，数据库存标识哈希、用户、CSRF token 和过期时间，并建立 TTL 索引；每次请求仍显式检查过期时间。

发布时用 MongoDB 事务原子创建快照、切换发布指针。提交事务中校验当前发布版本、状态和截止时间，并更新问卷 submissionFence，使提交与关闭、重新发布、调整截止时间发生写冲突时重试并重新读取；正式答卷与这次写入一起提交或回滚。截止时间按事务内校验时刻判断。

技术字段：Survey.revision 用于编辑乐观锁，versionCounter 用于发布序号，submissionFence 用于并发协调；Response.payloadHash 用于规范化请求的幂等比较。这些不是新增业务统计。嵌入题目、选项的标识以 24 位十六进制字符串保存，集合级关联以 ObjectId 保存。

数字答案采用 BSON Decimal128，最多 34 位有效数字，超限明确拒绝，避免静默舍入；规则中的十进制值也按精确十进制解析。接口数字答案返回十进制字符串，客户端不先转普通浮点数。

业务为四个集合，登录支持另有 sessions 集合。MongoDB 使用项目目录下独立数据路径、27018 端口与单节点副本集；不修改已有 MongoDB 服务。

用户不设题目文字、选项文字、题目数的业务上限，不代表绕过数据库和请求体的固有限制；具体实现若触及限制需明确提示，不静默截断数据。
